# Benchmark: ast-walk branch vs released coverage.py 7.15.0

Branch under test: `ast-walk` at 11a874e ("only walk statement nodes when
scanning for defs and classes"), which replaces `ast.walk` with a
statement-only tree walk in `PythonParser._raw_parse` and
`AstArcAnalyzer.analyze`. Verified before benchmarking that the installed
packages differ (released 7.15.0 has no `walk_statement_nodes`).

Workload: pyca/cryptography 49.0.0 test suite (4,264 tests passed, 208
skipped), used to collect coverage data and generate reports.

- Date: 2026-07-04
- Machine: 4-core x86_64 Linux container, 15 GiB RAM
- Python: CPython 3.11.15
- Released: `coverage==7.15.0` wheel from PyPI (C tracer)
- Branch: this repo installed via `pip install .` (7.15.1a0.dev1, C tracer
  compiled locally)
- Coverage scope: `--source=cryptography,tests` — 200 measured files,
  26,115 statements. Branch coverage (`--branch`) matches cryptography's
  own `[tool.coverage.run] branch = true` config and exercises the
  `AstArcAnalyzer.analyze` change; line coverage exercises only the
  `_raw_parse` change.

## Run phase (`coverage run --branch -m pytest tests/ -q`)

Interleaved runs; baseline without coverage is 37.4s. One warm-up pair
discarded as an outlier (background load).

| configuration        | runs               | median |
|----------------------|--------------------|--------|
| released 7.15.0      | 37.5, 37.3, 37.2   | 37.3s  |
| ast-walk             | 38.0, 37.8, 37.4   | 37.8s  |

Unchanged within noise, as expected: the parser isn't on the run path,
and tracing overhead is small for this suite anyway (most work happens in
cryptography's Rust extension).

## Report phase

All report commands read the *same* canonical data file, so both versions
parse identical data. Five iterations per command per version, interleaved;
medians of wall-clock time for the whole CLI invocation.

### Branch-coverage data (cryptography's real config)

| command  | 7.15.0 | ast-walk | delta  |
|----------|--------|----------|--------|
| report   | 4.25s  | 3.83s    | -10.0% |
| html     | 12.88s | 12.27s   | -4.7%  |
| xml      | 4.77s  | 4.38s    | -8.2%  |
| json     | 5.38s  | 5.10s    | -5.2%  |
| lcov     | 7.85s  | 7.21s    | -8.2%  |

### Line-coverage data

| command  | 7.15.0 | ast-walk | delta  |
|----------|--------|----------|--------|
| report   | 4.35s  | 3.67s    | -15.5% |
| html     | 13.07s | 12.38s   | -5.3%  |
| xml      | 4.88s  | 4.36s    | -10.7% |
| json     | 5.55s  | 5.20s    | -6.3%  |
| lcov     | 7.81s  | 7.28s    | -6.7%  |

The win is proportionally largest where parsing dominates the command
(`report`, `xml`) and smallest for `html`, which spends most of its time
rendering. Absolute medians should only be compared within a table —
the two datasets were measured in separate sessions with slightly
different ambient load — but each table's rel/branch pairs were
interleaved back-to-back, so the deltas are trustworthy.

## Output equivalence

For the branch-coverage data, all five report formats were generated by
both versions and compared: `report` text, JSON, and LCOV are
byte-identical; XML and all 200 HTML pages are identical after stripping
the embedded coverage.py version string and timestamp. The
`AstArcAnalyzer.analyze` rewrite dispatches to the only `_code_object__*`
handlers that exist (Module, FunctionDef, AsyncFunctionDef, ClassDef),
so no handler was orphaned.

## Conclusion

On a realistic large-suite reporting workload, the ast-walk change makes
report generation 5–15% faster depending on format (≈10% for the common
`coverage report`/`xml` cases with branch coverage) with byte-identical
output, and leaves run-phase performance untouched.

## Reproducing

```sh
python -m venv venv-rel && venv-rel/bin/pip install coverage==7.15.0
python -m venv venv-branch && venv-branch/bin/pip install <this repo>
# both venvs: pip install cryptography pytest pytest-benchmark pretend certifi iso8601
git clone --depth 1 --branch 49.0.0 https://github.com/pyca/cryptography.git
pip install ./cryptography/vectors   # in both venvs
cd cryptography
coverage run --branch --source=cryptography,tests -m pytest tests/ -q
./bench_reports.sh <data-file>       # times report/html/xml/json/lcov x5
```
